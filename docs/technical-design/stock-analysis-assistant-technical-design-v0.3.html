1设计原则与改动护栏

编码时有 8 条原则不能违反、7 条护栏不能越。它们决定了「哪些能复用、哪些必须新建、哪些碰都不能碰」。

8 条设计原则（DP-1 ~ DP-8）

DP-1 复用优先

能用现有能力的，不另起一套；新增 ≠ 修改现有。避免重复造轮子，也避免动了不该动的地方。

DP-2 口径隔离

本助手模块与主流程口径隔离，主流程不感知本助手存在。两边各跑各的，互不污染。

DP-3 单一真值

引擎每交易日盘后只跑一次，WebUI / 通知 / 卡片 / 导出四处读同一份快照，禁止各自重算；默认 T 20:00 一条推送（时点可配，多时点同源），T+1 不再推送。

DP-4 决策归代码，措辞归 LLM

LLM 只进文案层，不进评分 / advice / 风险 / 回测。数字和结论永远由代码算。

DP-5 可复现

同 calc_version + 同快照 → 同结论；参数改了不追溯历史（快照只追加不改）。

DP-6 只收紧不放宽

阶段门、风险信号都是事后收紧层，不改写评分逻辑。只会让动作更保守，不会更激进。

DP-7 降级优于编造

数据不足时标注降级，不推测、不编造、不阻塞报告。宁可写「数据不足」也不硬凑。

DP-8 硬护栏不可越

现有 11 条路由、页面组件、Shell、菜单、后端静态服务、主流程 Agent/Skill 都不得修改。

3数据获取与存储 C2

现状的存储只有一层、且是前复权落库、只取 30 天——不够用。方案改成四层存储，并把复权口径彻底拆开。

图 3-1 · 四层存储：原始 / 派生 / 快照 / 用户输入，职责不混层

复权口径：存什么 ≠ 算什么 ≠ 展示什么

现状是「前复权落库」，每次除权都会重写历史，和「不复权展示」冲突，也会让回测断裂。方案把三件事拆开：

用途口径理由
L1 存储不复权原始价 + adj_factor原始价是唯一事实，因子可重算任意复权序列；前复权落库会每次除权改写历史
页面展示 / 触发价不复权与券商盘面一致，用户可直接照抄设单
指标计算 / 回测后复权派生（原始价 × 累计因子）避免除权跳空被误判成「破位」；回测收益可含分红再投
除权日展示层标注「不可直接比较」与既有 P0-2 一致，给前收调整说明
硬护栏：若实测发现 adj_factor 免费源拿不到，退化为「本地按除权事件表推算因子」，但绝不退回前复权落库。

缺口检测与补洞

≤ 3 日缺口

自动补。正常的小中断，系统自己补齐，不影响生成。

> 3 日缺口

标 stale、阶段降 S0、不生成条件计划。宁可标数据不足，不硬凑。

取数失败

保留上次数据、全链路标 stale、「数据非最新」。不静默用旧数据冒充当日。

改参数怎么留痕（不搞版本号）

基线 + 单项覆盖

当前值 = 三档基线之一 + 你单独改的项。页面显示「标准档 · 2 项自定义」。

下一次快照生效

参数改了不影响当天已出的结论；当天快照只追加不改，历史永远可复现。

append-only 记录

每次变更记一条（可回滚，回滚也记一条）。不引入配置版本号，用 param_hash 随快照留痕。

param_hash 与 calc_version 分开：param_hash 是「参数数值指纹」，calc_version 是「规则版本指纹」（战法启停、维度权重、判定结构、temperature）。两者都随快照留痕，保证同 calc_version + 同 param_hash + 同快照 → 同结论。

7验证与回测 C6

两件事分开做：纸面回看验证「同数据同结论」，回测验证「胜率」。两者都不是预测，只作验证记录。

纸面回看两步法 不测胜率

第一步：1 只样例逐字段核对（输入 → 规则 → 中间结果 → 最终结论），每个数值回溯八字段。

第二步：10 只 × 5 日，检查跨标的、跨日的一致性。成功标准：无前后矛盾、S0 显式标因、S5 不落成假震荡。

回测引擎扩展 测胜率

现有引擎是后验评估，不模拟条件单成交。须扩展「条件计划回测模式」：价格触发、股数资金占用、T+1、部分成交/跳空、多分支组合、分红成本、未闭合仓位。

样本内外分离防过拟合；已闭合回合数不足只报计数不报胜率。

连续观望天数无超长连续观望同同
强制分阶段统计：回测结果按 S1–S5 分阶段统计胜率/盈亏比/回合数。S5（无结构）的回合数应显著低于其他阶段——如果 S5 回合数很高，说明判定出了问题。
