## 1. 推送时序：当日复盘 vs 次日盘前建议

用户最初提出的时序（**已被 2026-11-24 R23 替代**）：当日 20:00 前跑完 → 20:00 推送当日复盘 → 次日 8:00 推送当日盘前操作建议。最终拍板见 §1.2。

### 1.1 两份推送内容一样吗？（双推送设想下的比较，最终方案见 §1.2）

**不一样，但决策字段会高度重合。** 按现有文档口径：

| 维度 | 当日 20:00「复盘」 | 次日 8:00「盘前操作建议」 |
| --- | --- | --- |
| 定位 | 回看，回答「今天计划 vs 实际如何」 | 决策，回答「明天怎么做」 |
| 文档出处 | §5.11.6 复盘 + §3.6「复盘问答」 | §3.5.3 / §3.5.3.1 通知推送、FR-9.5 |
| 数据基础 | 当日收盘数据 + 当日已生成的快照 | 同一交易日收盘数据（盘前口径 §8.2，不纳入隔夜消息/集合竞价/当天新闻） |
| 内容 | 条件计划触发情况、跳空标注、实际走势对照；**只读快照、不重算、不改当日结论**；标「仅回看，不构成新建议」 | 七段固定结构：①头部（数据日期/快照/版本/来源）②一句话（大盘+动作计数）③风险 ④待办 ⑤阶段 ⑥条件计划 ⑦声明 |
| 是否含操作意见 | **不含新建议** | **含**（操作意见 + 条件计划 + 风险提醒摘要） |
| 合规标注 | 「仅回看，不构成新建议」 | 静态计划不下单不盯盘 + 免责声明 |

**关键重合点**：因为 20:00 与次日 8:00 之间不引入新数据（NG-1 / FR-8.4 明确「开盘后不更新结论、不纳入隔夜消息」），两处推送里的**操作意见、趋势/位置、阶段、关键价位、条件计划、风险等级会逐字相同**。若不加区分地各推一次，用户实际会收到两份几乎一样的文本。

### 1.3 R24 追加拍板：推送时点配置化（2026-11-24）

用户追加原话：「而且定时推送这个应该是配置项，后续可以快速修改定时时间等等，支持crontab类似的配置，一天重复多次推送等等。但如何判断是否为交易日呢？不是交易日不推送，或在文字提醒非交易日等」。经确认框三项拍板：

| 决策点 | 采用 | 否决的替代 | 对 R23 的影响 |
| --- | --- | --- | --- |
| 多时点内容 | **默认单推、多次同源**：时点可配、默认仍 20:00 一条；配多时点时每次读同一份 T 日快照、推相同文本，不重算、不产生新 `advice` | 按时点分工不同内容（会重开 R23 内容结构）；仅时点可配不谈多次（不满足用户明确诉求） | **R23 的单推内容口径保留为默认值**，不重开早/晚分工 |
| 非交易日处置 | **做成开关、默认不推**：`non_trading_action` 默认 `skip`；可选 `notify_skip` 只发一条短提醒，两值都不生成快照/卡片 | 维持完全不推（不满足提醒诉求）；总是发提醒（改变 R23 默认值） | 不推翻 R23 默认，但**恢复原话第 8 条的提醒能力为可选项** |
| cron 程度 | **简写 + 完整 cron 都支持**：`HH:MM` 逗号列表与 5 字段 cron 并存 | 仅完整 cron（弃用 HH:MM 习惯）；仅多时间点（不满足 crontab 类似） | 只改「何时推」，不改「推什么」 |

**交易日判断机制（用户提问的正面回答）**：现有 `src/core/trading_calendar.py` 已具备能力——基于 `exchange-calendars>=4.13.0`（已在 requirements.txt），A 股用 `XSHG` 日历，`build_market_phase_context("cn")` 返回 `is_trading_day`，时区用 `Asia/Shanghai`。**关键坑**：`is_market_open()` 是 fail-open（日历不可用时返回 `True`），不可用于门控；必须用 fail-closed 的 `build_market_phase_context()`，`None`/`UNKNOWN` 按非交易日处理并告警。cron 只决定「何时尝试」，门控决定「是否真跑」，两者独立（需求 FR-8.7 / 方案 §2.4）。

**文档落点**：需求 v2.6：§0 R24 全局约定、FR-9.13、FR-8.6 修订、FR-8.7、B50、R24、附录 C.15；技术方案 v0.3：§2.1 架构、§2.3 时序、§2.4 调度配置与时区门控、§5.2 调度配置组、§6.3 多时点同源投递、§9.2 M18、§10 映射、HTML 时序图重画。

> **决策记录**：状态＝口径层已拍板（整体需求仍草案 / 待批准）；决策人＝用户本人，2026-11-24 确认框三项选定；依据＝用户原话 + 三项选择；保留意见＝R23 单推内容、决策字段、阈值、守卫链、七段结构、字段契约零改动；复审触发＝用户要求多时点推不同内容、盘中推送、或非交易日生成正式报告。
