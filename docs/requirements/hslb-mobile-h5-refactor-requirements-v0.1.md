## 1. 背景与目标

### 1.1 背景

现有高抛低吸 H5 是改造 `apps/dsa-web/` 桌面端工程的产物：首页 `HomePage` 承载了大量桌面端能力（多标签、批量操作、筛选面板），个股详情 `/m/stocks/:code` 也套在统一的 `Shell` / `MobileShell` 里。手机打开后信息密度过高、路径不直观，且与桌面端相互牵连，改一处页面容易影响另一处。

本次希望**新开一套独立的移动端页面**，只服务一个明确场景：**收盘后打开手机，看一眼自选股该不该动，点进去看为什么**。

### 1.2 目标

- **G1｜独立入口**：新 URL 独立访问、独立渲染，不嵌入旧页面、不套旧 Shell、不复用旧首页布局。
- **G2｜列表一眼可读**：打开即见自选股清单，每行给出「名称 + 代码 + 当日价格 + 操作建议」，3 秒内判断哪只该动。
- **G3｜详情可下钻**：点击进入详情，看到当日四价、建议总结，并可展开查看分析过程（技术面 / 消息面 / 风险 / 大盘 / 板块）。
- **G4｜后台最小改动**：复用现有 `decision_signals`、`StockOverviewService`、行情与事件源，不新建分析管线、不改数据结构。
- **G5｜移动优先**：为单手操作与窄屏设计（点击区、字号、安全区、无 hover 依赖），不做桌面适配。

### 1.3 非目标（本期明确不做）

- **NG1**：不改信号算法、不重算指标、不改风控口径（四端同源约束不变）。
- **NG2**：不做盘中实时盯盘 / 分钟级刷新（沿用 NG4 基线）。
- **NG3**：不在新页面做写操作（加/减自选、改持仓、调权重仍走旧页或对话 + `action_service`）。
- **NG4**：不替换旧页面。旧 `/`、`/m/stocks/:code` 保留可用，新页面并行上线。
- **NG5**：不做登录 / 用户体系改造；沿用内网免登录形态（是否放行见 D6）。

## 2. 页面与路由设计

### 2.1 路由

| 页面 | 路由（建议） | 说明 |
| --- | --- | --- |
| 自选股列表（首页） | `/h5` | 新 H5 首页，独立入口 |
| 个股详情 | `/h5/stocks/:code` | 例：`/h5/stocks/601919` |

- 与现有 `/m/stocks/:code` **不冲突、不互相跳转**，两套页面并行。
- 备选前缀：`/hslb`、`/app`（见 D1）。前缀一经确认不再改动，**推送深链会写入历史消息**，改名成本高。

### 2.2 渲染方式（关键约束）

新 H5 必须**在鉴权判断之前独立渲染，且不套 `Shell` / `MobileShell`**，与现有大屏 `/screen` 同一模式（`apps/dsa-web/src/App.tsx` 中 `location.pathname === '/screen'` 的早返回分支）：

```
/h5、/h5/stocks/:code  →  StandaloneRouteBoundary  →  独立页面（无侧边栏 / 无底部 Tab）
```

理由：手机端不需要站点导航；独立渲染可避免旧 Shell 的鉴权跳转、埋点与聊天浮层干扰。

### 2.3 与旧页面的关系

| 项 | 旧 | 新 |
| --- | --- | --- |
| 首页 | `/`（桌面能力全集） | `/h5`（仅自选股列表） |
| 详情 | `/m/stocks/:code`（含加自选、调整面板、K 线） | `/h5/stocks/:code`（只读：结论 + 四价 + 分析过程） |
| 推送深链 | `daily_digest.py` 拼 `/m/stocks/{code}?from=push` | 是否切到 `/h5/stocks/{code}`（见 D7） |

## 3. 功能需求

### FR-L · 列表页（`/h5`）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-L1 | 顶部显示页面标题与**数据截止时间**（如「数据截至 2026-10-20 收盘」），让用户知道看到的是哪天的结论 | 必须 |
| FR-L2 | 列表**逐行**展示自选标的，每行必须包含：**标的名称、代码、当日价格、操作建议** | 必须 |
| FR-L3 | 「当日价格」需同时给出**涨跌幅**（红涨绿跌），否则用户无法判断价格含义 | 必须 |
| FR-L4 | 「操作建议」以**彩色标签**呈现，取值见 §3.3；紧急信号（止损/清仓）需有视觉强调并**置顶** | 必须 |
| FR-L5 | 点击整行进入详情页 `/h5/stocks/:code`；点击区不小于 44px 高 | 必须 |
| FR-L6 | 支持**下拉刷新**；刷新时保留旧数据不被清空（避免白屏） | 必须 |
| FR-L7 | 列表为空时给出明确引导（「暂无自选标的，请在设置中添加」），不显示空表格 | 必须 |
| FR-L8 | 单只标的行情缺失时，该行价格显示 `-`，建议正常显示，不整行报错 | 必须 |
| FR-L9 | **无信号**的标的显示「暂无信号」，不得默认显示「观望」（避免把"没算"误读成"建议按兵不动"） | 必须 |
| FR-L10 | 列表排序：紧急 → 有明确操作（建仓/加仓/减仓/清仓）→ 持有 → 观望 → 无信号 | 期望 |
| FR-L11 | 列表显示持仓盈亏（需已录入成本） | 可选（见 D8） |

### FR-D · 详情页（`/h5/stocks/:code`）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-D1 | 顶部显示**标的名称 + 代码**，并提供返回列表的入口 | 必须 |
| FR-D2 | 展示**当日最高价、最低价、开盘价、收盘价**；盘中打开时「收盘价」位显示最新价并标注「盘中」 | 必须 |
| FR-D3 | 展示**操作建议总结**：一句话人话结论 + 建议动作标签 + 理由要点 | 必须 |
| FR-D4 | 总结区右上角有**展开/收起按钮**（默认收起），点击展开分析过程 | 必须 |
| FR-D5 | 展开区按**维度分块**呈现：技术面、消息面、风险、大盘、板块（可再含基本面） | 必须 |
| FR-D6 | 每个维度需给出「结论 + 依据」，依据为空时明确显示「该项暂无数据」，**不得留白或编造** | 必须 |
| FR-D7 | 展开区保留**四要素**：参考价位、止损价、目标价、仓位建议（可执行信息不能只藏在文字里） | 必须 |
| FR-D8 | 展示**建议生成时间**（与行情时间分开标注），避免把昨天的结论当成今天的 | 必须 |
| FR-D9 | 底部常驻**免责声明**（复用现有 `DISCLAIMER` 文案） | 必须 |
| FR-D10 | 数据降级时（行情失败、事件源不可用）展示可折叠的说明条，不静默吞掉 | 必须 |
| FR-D11 | 60 日迷你 K 线 | 可选（M2） |
| FR-D12 | 从详情返回列表时保持列表滚动位置 | 期望 |

### 3.3 操作建议枚举与展示映射

后端 `decision_signals.action` 现有 8 态（`src/services/daily_digest.py` → `ACTION_LABELS`）。新页面展示建议按下表收敛：

| 后端 action | 现有标签 | 新 H5 展示 | 颜色语义 |
| --- | --- | --- | --- |
| `build` / `buy` / `dip_buy` | 建底仓 / 建仓买入 / 超跌抄底 | **建仓** | 红 |
| `add` | 加仓 | **加仓** | 红 |
| `hold` | 持有 | **持有** | 中性 |
| `reduce` | 减仓 | **减仓** | 绿 |
| `sell` / `clear` | 清仓 | **清仓** | 绿（加紧急标记） |
| `wait` / `watch` | 观望 | **观望** | 灰 |
| `avoid` | 回避 | **观望 + 风险标记** | 灰（见 D2） |

> 需求原文「观望、加仓、减仓、清仓、减仓」中第五项疑为「建仓」，上表按 6 类收敛，待 D2 确认。

### 3.4 通用需求（NFR）

| 编号 | 需求 |
| --- | --- |
| NFR-1 | 首屏可交互时间目标 ≤ 2s（本地内网、8 只标的），列表串行取数不可接受，需并发或短缓存 |

## 4. 现状对照与差距

> 结论：**页面层是新建，数据层约 80% 可复用**，真正缺口只有「列表轻量接口」与「大盘/板块两块分析依据」。

| 需求 | 现有能力 | 判定 | 说明 |
| --- | --- | --- | --- |
| 独立 URL / 不嵌旧页 | `/screen` 已有「鉴权前独立渲染」先例 | 复用 | App.tsx 加早返回分支即可 |
| 名称 + 代码 + 建议 | `GET /api/v1/stocks/{code}/overview` 返回 `name/action/action_label/conclusion` | 复用 | 单只可用，**列表需 N 次调用** |
| 当日价格 + 涨跌幅 | `GET /api/v1/stocks/{code}/quote` 返回 `current_price/change_percent` | 复用 | — |
| **列表（一次拿全）** | `GET /api/v1/stocks/watchlist` **只返回代码数组**（读 `STOCK_LIST`）；`/api/v1/screen/snapshot` 有卡片但会连带算指数/持仓/复盘，偏重 | **缺口** | 需新增轻量列表接口（见 §5.2） |
| 当日开/高/低/收 | `/quote` 已返回 `open/high/low/current_price`（数据层 `stock_service.get_realtime_quote` 完整映射） | 复用 | 旧详情页 `overview.quote` 只透传了 3 个字段，新页直接调 `/quote` 即可，**无需改后端** |
| 建议总结 + 理由 | `overview.conclusion` / `reason` | 复用 | — |
| 技术面依据 | `metadata.trend / weekly_trend / multi_period_conflict`、`score`、`evidence.reasons` | 复用 | 已可组装「趋势 + 周线 + 场景 + 评分」 |
| 风险依据 | `risk_summary`、`evidence.risk_reasons`、`is_urgent`、仓位建议 | 复用 | — |
| 消息面依据 | `events[]`（事件源，情报 + 预警） | 复用 | 文案级，无结构化情绪分 |
| **大盘** | 信号里的 `market_phase` 固定为 `postmarket`（表示"盘后"，**不是大盘状态**） | **缺口** | 指数数据可通过 `weekly_review_service.DEFAULT_INDEX_CODES` + 历史行情算当日涨跌 |
| **板块** | `data_provider` 有 `get_sector_rankings()`（行业板块涨跌排行），但**无"个股→所属行业"常规映射**（仅涨停池附带 `industry`） | **缺口** | 需补一次行业归属取数，或本期降级为「未接入」 |
| 基本面 | `factor_weight_service` 明确 `fundamental` 当前「无数据」 | 缺口 | 本期不做，如实展示「暂无数据」 |
| 无信号语义 | `overview` 无信号时 `action` 默认 `watch`（观望） | **风险点** | 前端必须靠 `degraded` 文案或 `signal_id is null` 区分「无信号」与「建议观望」 |
| 自选股数据源 | `watchlist_items` 表（含 `asset_type`、ETF）是 HSLB 权威源；`/stocks/watchlist` 读的是 `STOCK_LIST` 配置 | **不一致** | 新列表接口**必须读 `watchlist_items`**，否则 ETF 与对话增删的标的会漏 |

## 5. 接口设计（只读）

### 5.1 详情页：全部复用，零改后端

| 用途 | 接口 | 关键字段 |
| --- | --- | --- |
| 四价 + 涨跌幅 | `GET /api/v1/stocks/{code}/quote` | `open/high/low/current_price/prev_close/change_percent/update_time` |
| 建议 + 分析过程 | `GET /api/v1/stocks/{code}/overview` | `action/action_label/conclusion/reason/score/confidence/is_urgent/stop_loss/target_price/entry_zone/position_ratio_label/factors/events/risk_summary/degraded/disclaimer/signal_created_at` |

> 建议在 `overview` 上**追加字段**（不破坏旧客户端）：`analysis` 结构，包含五维摘要；或由前端用现有 `factors[]` + `evidence` 组装。二选一见 D4。

### 5.2 列表页：新增轻量接口（唯一的后端新增）

```
GET /api/v1/h5/watchlist
```

响应（示意）：

```json
{
  "as_of": "2026-10-20",
  "quote_as_of": "2026-10-20T15:00:00",
  "items": [
    {
      "symbol": "601919",
      "name": "中远海控",
      "asset_type": "stock",
      "price": 15.32,
      "change_percent": 1.24,
      "action": "reduce",
      "action_label": "减仓",
      "has_signal": true,
      "is_urgent": false,
      "scenario_label": "上涨趋势",
      "signal_created_at": "2026-10-20T20:00:12"
    }
  ],
  "degraded": [],
  "disclaimer": "..."
}
```

实现要点：

1. 数据源：`WatchlistService.list_watchlist(enabled_only=True)`（`watchlist_items`）；
2. 每只标的复用 `StockOverviewService`，**但跳过事件聚合与因子组装**（列表用不到，且事件源是主要耗时项），建议给 service 增加 `light=True` 参数；
3. 并发取数 + 15s 短缓存（与 `/screen` 的 `HSLB_SCREEN_CACHE_SECONDS` 同思路）；
4. 单只失败降级为 `price: null, has_signal: false`，不返回 5xx；
5. 排序可在服务端固定，也可交给前端。

## 7. 优化建议与查漏补缺

> 以下不在原始需求里，但会直接影响"手机上好不好用"，建议一并纳入 M1（标 ★ 为强烈建议）。

**信息完整性**

1. ★ **价格必须带涨跌幅**，否则"当日价格"没有参照系。
2. ★ **区分「无信号」与「建议观望」**：现在两者都渲染成"观望"，会让人误以为系统看过并建议不动。列表项加 `has_signal`，无信号显示灰色「暂无信号」。
3. ★ **建议时间与行情时间分开标注**：盘后看的是收盘价与当日结论；次日盘中打开，价格是新的、结论是旧的，必须让用户看出来。
4. 列表加「距止损 / 距目标」百分比，比单个止损价更有决策价值（数据已在 `overview` 里）。
5. 列表可加"今日有变化"标记（与上一交易日信号相比动作变化），减少重复阅读。

**可用性**

6. ★ 展开区的**每个维度必须有结论句**，不要只堆指标名（"MA5 上穿 MA10" 对小白无意义，应写"短期均线转强，短线偏多"）。
7. 展开按钮文案用「看分析过程 / 收起」，并在按钮旁提示维度数量（如「5 个维度」），提升点击意愿。
8. ★ 详情页**不要在一级屏放写操作**（改持仓/加自选），保持只读心智；需要时给一个"去旧版调整"的次级入口。
9. 列表行右对齐建议标签、价格区固定宽度，避免不同长度股票名造成锯齿。

**性能与稳定性**

10. ★ 列表**不要 N 次串行请求**（8 只 × 单只接口 ≈ 数秒），走新增的聚合接口 + 并发 + 短缓存。
11. 展开区数据随详情接口一次返回，**展开不再发请求**，避免"点了转圈"。
12. 刷新采用"旧数据 + 顶部 loading"，不要整页骨架闪烁。

**合规与观感**

13. 免责声明固定在详情页底部（列表页可放一行小字入口）。
14. 建议标签统一色系，避免"减仓"用红色造成方向误读（涨红跌绿已定，操作色需与涨跌色区分语义：建议"建仓/加仓"用红系描边、"减仓/清仓"用绿系描边、观望用灰）。

## 8. 确认事项（D1~D9 已按建议锁定）

| # | 事项 | 建议方案 |
| --- | --- | --- |
| D1 | 新 URL 前缀 | `/h5` + `/h5/stocks/:code`（备选 `/hslb`） |
| D2 | 操作建议展示枚举 | 6 类：建仓 / 加仓 / 持有 / 减仓 / 清仓 / 观望；`avoid` 归入观望 + 风险标记 |
| D3 | 总结区是否直接露出四要素（止损/目标/仓位） | **露出**（可执行信息不应藏在展开区） |
| D4 | 大盘 / 板块是否本期接入 | 大盘**本期接入**（指数当日涨跌，成本低）；板块**本期先显示「暂无数据」**，M2 补（需补个股行业归属取数） |

## 9. 风险与依赖

| 风险 | 影响 | 应对 |

### 11.2 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/h5/watchlist` | 读 `watchlist_items`（空表回退 `STOCK_LIST`），并发聚合 + 短缓存；`refresh=true` 绕过缓存 |
| `GET /api/v1/h5/stocks/{code}` | 四价 + 建议总结 + 五维分析（技术面 / 消息面 / 风险 / 大盘 / 板块） |

服务层：`src/services/h5_service.py`；响应模型：`api/v1/schemas/h5.py`；端点：`api/v1/endpoints/h5.py`。

### 11.3 关键口径

- 8 态动作 → 6 类展示，`avoid` 归入观望并保留风险标记；
- 无信号 → `has_signal=false` + 「暂无信号」，**不等同于观望**；
- 列表排序：紧急 → 建仓/加仓/减仓/清仓 → 持有 → 观望 → 无信号；
- 大盘：上证 / 深证 / 创业板指数当日涨跌；**板块：显式 `available=false`，M2 补齐**；
- 四要素（参考价位 / 止损 / 目标 / 仓位）常驻总结区，不藏进展开区。
