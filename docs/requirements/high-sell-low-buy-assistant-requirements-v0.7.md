## 1. 背景与目标

### 1.1 背景

需求提出者是**金融新手（小白）**，个人投资 A 股。日常工作无法盯盘，希望有一套自动化工具，在**每天收盘后**与**每周末**自动扫描自选股，基于技术指标与多维度信息，用**通俗易懂的方式**给出"高抛低吸"的操作建议，并通过**多端交互**触达（消息推送 / 大屏 / H5 / AI 对话），让本人不必盯盘也能掌握买卖节奏。

### 1.2 目标（Goal）

- **G1｜有建议可执行**：对每只自选股，明确给出「做什么（买/加/减/清/观望）+ 为什么 + 具体价位 + 建议仓位」。
- **G2｜覆盖三类核心行情**：上涨、下跌、震荡三种趋势下，均有对应的判断规则与操作建议。
- **G3｜小白看得懂**：先用一句话"人话结论"说明该怎么做，专业指标依据作为可展开明细附后。
- **G4｜自动触达**：无需主动操作，收盘后自动推送每日概览，周末自动推送复盘报告。
- **G5｜贴合个人账户**：结合本人录入的持仓成本与仓位，给出针对性建议（如"浮盈 8%，破 5 日线建议减 3 成"）。
- **G6｜可信可验证**：策略上线前先经历史数据回测验证，不"拍脑袋上线"。
- **G7｜多端可交互**：同一份结论支持**消息推送、大屏、H5、AI 对话**四种触达与交互方式，既能被动接收，也能主动查看与对话操作。
- **G8｜买卖全闭环**：覆盖「**建仓 → 加仓 → 分批止盈 → 减仓 / 清仓**」完整买卖链路，每个环节均有主动提醒。
- **G9｜提醒必有技术依据**：每一条提醒（买 / 加 / 减 / 清）都必须能回溯到明确的技术指标与规则，禁止"只喊买卖不给依据"（见 FR-18）。

### 1.3 非目标（明确不做，划定边界）

- **NG1**：不做实盘自动交易，**不接入券商下单**。所有建议均需本人手动执行。
- **NG2**：不承诺收益、不构成投资建议（详见 NFR-5 合规与免责）。
- **NG3**：**标的范围 = A 股个股 + 场内基金（ETF / LOF，含港股主题 ETF，如 513530）**。首期不做港股 / 美股（直接交易）、期货、期权、**场外基金**、可转债。
- **NG4**：不做盘中实时（分钟级/秒级）监控与分析，只做**收盘后**与**周度**两个节奏。**大屏亦不做盘中盯盘监控**，仅做收盘后数据与报告的展示（见 FR-14.1）。
- **NG5**：不做社交、跟单、社区、组合分享等外围功能。
- **NG6**：不做实盘下单、不做券商账户直连、不做自动交易执行（AI 对话仅提供建议与记录回执）。

## 2. 用户画像与使用场景

### 2.1 用户画像

| 维度   | 描述                                  |
| ---- | ----------------------------------- |
| 身份   | 个人投资者，金融新手                          |
| 市场   | A 股                                 |
| 关注标的 | 自选股 **3~5 只**（回测样本：中远海控 601919、中国农业银行 601288） |
| 时间投入 | 无法盘中盯盘，每天收盘后 / 周末看一次                |
| 技术水平 | 不懂策略细节，需要"人话"解释；但希望保留可展开的专业明细       |
| 使用设备 | 手机为主（H5 / 消息 / AI 对话），电脑为辅（大屏 / 网页） |
| 部署环境 | **本地个人电脑、内网运行**，免登录鉴权                |
| 核心诉求 | 该不该动、动多少、什么价位动；不要天天被无效提醒骚扰          |

### 2.2 典型一天

> 15:00 收盘 → 系统自动分析自选股 → **20:00** 推送一条「每日概览」到企业微信 / 飞书 / 钉钉 → 本人下班后打开查看：先看每只股一句话结论，重点信号标红置顶；想深入时**点开进 H5** 展开看指标明细与 K 线图；有疑问**直接在对话里问**"为什么让我减仓"。

### 2.3 典型一周

> **周六** → 系统推送「周度复盘」→ 内容含：本周信号回顾与胜率、持仓盈亏与是否按建议执行（手动回填）、大盘与板块周度总结、下周关注标的与关键价位 → 需要时**在家用大屏或电脑网页**整体浏览一遍。

### 2.4 典型一次"想问就问"

> 盘中或任意时刻（非实时行情，仅基于最近收盘数据）→ 在机器人对话里发"茅台现在什么情况""KDJ 是什么意思""把技术面权重调到 60% 并把 600519 止损设为 15 元"→ 助手即时回答或执行并回执（**支持一句话多指令**）。

## 3. 名词解释（面向金融小白，产品内也应提供同类解释）

| 名词               | 通俗解释                                                 |
| ---------------- | ---------------------------------------------------- |
| K 线              | 每根柱子记录一段时间（日线即一天）的开盘、收盘、最高、最低价                       |
| 均线（MA5/10/20/60） | 最近 N 天收盘价的平均值连线，代表"平均成本"，用来判断趋势方向                    |
| 多头排列             | MA5 > MA10 > MA20 且向上，说明近期买盘强、趋势向上                   |
| MACD             | 衡量上涨/下跌动能的指标；红柱放大=动能增强，绿柱放大=动能衰竭；金叉偏多、死叉偏空           |
| KDJ              | 衡量短期超买超卖的震荡指标；J 值 > 100 偏超买，J 值 < 0 偏超卖；金叉/死叉给短期买卖提示 |
| RSI              | 相对强弱指标；> 70（或 80）偏超买，< 30（或 20）偏超卖                   |
| 布林带（BOLL）        | 以均线为中轨、上下各加减标准差形成的通道，价格常在中轨与上下轨间波动                   |
| 乖离率（BIAS）        | 现价偏离均线的百分比；正乖离过大易回调，负乖离过大易反弹                         |
| 缩量 / 放量          | 成交量比前几日明显减少 / 放大，反映买卖双方力量的强弱                         |
| 背离               | 价格创新高（新低）但指标没跟着创新高（新低），常预示趋势要反转                      |
| 支撑位 / 压力位        | 价格下跌时容易止跌的位置 / 上涨时容易受阻的位置                            |
| 箱体震荡             | 价格在一个上下边界明确的区间内反复波动，适合"贴底买、近顶卖"                      |
| 做 T              | 在已有持仓上，日内或短线先卖后买（或先买后卖），赚取波动差价                       |
| 止损               | 亏损达到预设条件时无条件卖出，防止小亏变大亏                               |
| 仓位 / 几成          | 你投入某只股票的资金占计划总资金的比例，如"3 成"=30%                       |
| 破位 / 变盘          | 价格有效跌破关键支撑（或突破关键压力），原趋势可能失效、需要换策略                    |
| 场内基金（ETF / LOF）   | 在交易所像股票一样买卖的基金；ETF 跟踪某指数（如 513530 跟踪港股通红利），LOF 既可申赎也可场内交易 |
| 折溢价率             | ETF 场内交易价相对其净值的偏离；溢价高说明买贵了、折价说明买便宜了，偏离过大时不宜追       |
| 跟踪指数 / 成分股       | ETF 所跟踪的指数及其成份股；基金没有个股财报，需用指数 / 成分股与基金分红替代        |
| 事件日历             | 财报预约披露、分红除权、解禁、股东大会等**已知日期**的提醒清单                    |
| 超预期 / 不及预期       | 财报实际业绩与市场预期（或同比 / 环比）的比较，超预期偏多、不及预期偏空                |

## 4. 功能需求（Functional Requirements）

> 优先级说明：**必须**=首期不可缺；**期望**=首期尽量有；**可选**=可后续迭代。  
> 涉及具体数值的，均为**建议默认值**，需支持在配置中调整，最终数值在方案阶段确认。

### FR-1 自选标的维护｜优先级：必须

- **FR-1.1** 支持通过**配置文件**维护自选股列表（A 股，3~5 只），配置项至少包含：股票代码、名称、持仓成本价、持仓比例/股数（FR-1.3 可留空）。
- **FR-1.2** 支持通过**机器人对话动态增删**标的，例如发送「添加 600519」「删除 600519」「查看自选股」（对话能力详见 FR-14.3）。
  - 增删后需向用户回执确认（加了什么、当前列表是什么）。
  - 需处理无效代码、重复添加、非 A 股标的等情况并给出明确提示。
- **FR-1.3** 支持维护**持仓信息**：成本价、持仓数量或比例（可部分录入，未录入的按"无持仓"处理）。**持仓由本人手动维护**（已确认），暂不对接券商账户。
- **FR-1.4** 配置文件与对话修改的数据需**保持一致**（同一份数据源，避免两处冲突）。
- **FR-1.5** 标的类型支持**个股 + 场内基金（ETF / LOF）**：系统需识别标的类型并按类型套用相应规则（详见 FR-19）；如港股红利 ETF **513530** 可直接添加。

### FR-2 行情数据获取｜优先级：必须

- **FR-2.1** 获取自选股的**日线历史数据**，至少覆盖近 120 个交易日（用于判断中长期趋势、箱体、均线斜率）。
- **FR-2.2** 获取**最新收盘价与当日成交量**，用于判断放量/缩量、破位/突破。
- **FR-2.3** 数据源需具备**失败降级**能力：单一数据源异常时自动切换备用源，不能因单点故障导致整个分析失败。
- **FR-2.4** 需能获取**大盘指数、所属行业/板块**数据，以支持 FR-7 的多维度判断。
- **FR-2.5** 需能获取**周线级别数据**，以支持 FR-3.3 的多周期判断。
- **FR-2.6** 对**场内基金**，需能获取**跟踪指数及成分股、基金分红**等数据，以支持 FR-19 的基金专属判断（并具备失败降级能力）。**折溢价率、规模 / 成交额**因免费数据源稳定性待验证，**本期降级为不做**（见 FR-19.2 与方案文档 R1）。

### FR-3 整体趋势研判｜优先级：必须

对每只标的首先判定**当前所处趋势状态**，作为后续所有建议的前提。

- **FR-3.1** 至少区分以下状态：
  | 状态               | 判定依据（建议默认，可调）                              |
  | ---------------- | ------------------------------------------ |
  | **上涨趋势**         | MA5 > MA10 > MA20 且 MA20 斜率向上；价格位于 MA20 上方 |
  | **下跌趋势**         | MA5 < MA10 < MA20 且 MA20 斜率向下；价格位于 MA20 下方 |
  | **震荡趋势**         | 均线纠缠（MA5/10/20 相互间距较小），价格在箱体/通道内反复         |
  | **变盘 / 突破**（补充）  | 放量突破箱体上沿或平台压力、或有效跌破关键支撑                    |
  | **高波动 / 异动**（补充） | 涨跌停、跳空缺口、单日振幅显著放大、消息驱动的急涨急跌                |
  | **背离**（补充）       | 价格与 MACD / RSI 出现顶背离或底背离                   |
- **FR-3.2** 趋势判定需**结合成交量**校验（缩量上涨/放量滞涨需给出不同解读）。
- **FR-3.3（已确认引入周线）** 需考虑**多周期一致性**：**引入周线级别判断**（日线 + 周线）；日线与周线趋势冲突时，需降级为"谨慎"并明确提示。
- **FR-3.4** 判定结果需给出**置信度或强度**（强/中/弱），而非只有"是/否"。
- **FR-3.5** 对**场内基金**，趋势以**场内价格 K 线**为主判断，并用**跟踪指数趋势**校验；当价格与指数背离时需提示（详见 FR-19.2）。

### FR-4 场景 A · 上涨趋势操作建议｜优先级：必须

- **FR-4.1（用户原始需求）** **跌破 5 日均线 → 提醒减仓**。
- **FR-4.2（细化建议）** 建议改为**分级减仓**：
  - 跌破 MA5 → 轻度减仓 / 预警（建议减 20%~30%）
  - 跌破 MA10 → 中度减仓
  - 跌破 MA20 → 趋势可能转向，重度减仓 / 离场
- **FR-4.3（补充）** 顶背离预警：价格创新高但 MACD / RSI 未同步创新高 → 减仓提示。
- **FR-4.4（补充）** 乖离率（BIAS）过大 → 提示短期过热，建议止盈部分仓位。
- **FR-4.5（补充）** 放量滞涨 / 长上影线 → 分歧信号，提示谨慎。
- **FR-4.6（补充·低吸来源）** 回踩 MA10 / MA20 **不破并企稳** → 给出**加仓低吸**机会（"高抛低吸"中"低吸"的主要来源）。
- **FR-4.7** 上涨趋势中需始终给出**移动止损位**（随均线上移）。

### FR-5 场景 B · 下跌趋势操作建议｜优先级：必须

- **FR-5.1（用户原始需求）** **下跌趋势告警 + 建议减仓**。
- **FR-5.2（用户原始需求）** **止跌判断**：判断下跌是否可能结束，建议量化以下信号（满足越多越可信）：
  - 缩量止跌（成交量明显萎缩至地量）
  - 长下影线（盘中下探后收回，显示买盘承接）
  - KDJ 超卖后金叉（J 值由 < 0 回升并上穿）
  - MACD 绿柱持续缩短
  - 底背离（价格创新低但 MACD / RSI 未创新低）
- **FR-5.3（用户原始需求）** **超跌抄底判断**：出现极致超跌时判断是否可加仓抄底，建议参考：
  - RSI 进入超卖区（建议阈值 < 20，可调）
  - KDJ 的 J 值 < 0
  - 负乖离率（BIAS）过大（建议阈值 < -10%，可调）
  - 价格触及/跌破布林带下轨
- **FR-5.4（强制补充）** 一切抄底建议**必须同时给出止损位**（建议设在近期低点下方），并明确"分批建仓、抄底失败立即离场"，禁止只喊抄底不给风控。
- **FR-5.5** 抄底建议的仓位需**明显小于**上涨趋势中的加仓建议（如首笔不超过 2~3 成）。

### FR-6 场景 C · 震荡趋势操作建议（做 T）｜优先级：必须

- **FR-6.1（用户原始需求）** 给出**做 T（高抛低吸）的价格区间**：建议用布林带上下轨 / 箱体上下沿 + 支撑压力位共同确定。
- **FR-6.2（关键约束）** 建议的买卖价差**必须覆盖交易成本**：A 股来回成本（佣金 + 印花税 + 过户费）约 0.1%，故**价差过小（建议 < 1.5%，可调）时不建议做 T**，并说明"做了反而亏手续费"。
- **FR-6.3（补充）** 给出**网格建议**：网格间距、每格仓位、最多几格。
- **FR-6.4（补充）** 明确**区间失效条件**：一旦有效突破箱体/通道，立即停止做 T 并切换策略（向上转多头、向下转离场）。
- **FR-6.5** 震荡趋势中仍需提示"趋势不明时可空仓观望"。

### FR-7 多维度分析与权重调节｜优先级：必须

- **FR-7.1** 综合以下**四类维度**形成判断：
  1. **技术面**（K 线、均线、KDJ、RSI、MACD、布林带、量价、支撑压力）
  2. **消息面**（个股新闻 / 公告 / 情绪）
  3. **基本面**（估值、业绩等；**场内基金无个股财报，以跟踪指数 / 成分股基本面与基金分红替代**）
  4. **行业 / 大盘 / 板块**（指数趋势、板块轮动、行业景气度）
- **FR-7.2** 四个维度支持**可调节权重**。默认按「**偏技术面**」配置（建议默认值，可调）：
  | 维度       | 建议默认权重 |
  | -------- | ------ |
  | 技术面      | 45%    |
  | 行业/大盘/板块 | 25%    |
  | 消息面      | 15%    |
  | 基本面      | 15%    |
- **FR-7.3** 支持**展开查看各维度明细**：每个维度给出其独立结论（偏多 / 中性 / 偏空）及依据，用户可逐项展开。
- **FR-7.4** 综合结论需**可解释**：说明是哪些维度共同导致了当前建议，避免"黑箱打分"。

### FR-8 操作建议输出规范｜优先级：必须

- **FR-8.1** 每条建议必须包含四要素：**方向**（买 / 加仓 / 减仓 / 清仓 / 观望）+ **理由** + **具体价格**（买卖触发价 / 止损价，尽量给出区间）+ **建议仓位**（几成）。
- **FR-8.2** 建议需**针对持仓**：结合 FR-1.3 的成本价与仓位，给出如"当前浮盈 8%，跌破 MA5 建议减 3 成"的个性化表述。
- **FR-8.3** 无明确机会时必须**明确写"暂不出手/观望"**，禁止为凑内容给出无依据建议（避免过度交易）。
- **FR-8.4** 建议需给出**操作纪律卡**（每只股固定展现）：买入条件 / 加仓条件 / 减仓条件 / 止损位，让本人一页看清。

### FR-9 风控规则（止损止盈与仓位）｜优先级：必须

- **FR-9.1** 止损方式：采用**技术位止损**（跌破关键均线 5/10/20 日线，或跌破近期结构低点）。
- **FR-9.2** 每一条买入 / 加仓建议**必须附带止损位**，无止损不给出买入类建议。
- **FR-9.3** 提供**仓位管理规则**（建议默认，可调）：
  - 首次建仓不超过总仓位的 3 成
  - 趋势确认后按**金字塔节奏**分批加仓至上限（越涨加得越少，建议不超过 6~7 成，详见 FR-17.3）
  - 减仓同样分批，不一次性清仓（除非触发硬止损）
- **FR-9.4** 触发止损条件时，推送中需**显著提示**（见 FR-10.4）。
- **FR-9.5 止盈方式：分批止盈（已确认）**：采用**分批止盈**，禁止"一把梭"式全清。三层配合、分批执行、不追求卖在最高点，建议默认方案如下（可配置）：

  | 层级    | 触发条件            | 动作（建议默认）        |
  | ----- | --------------- | --------------- |
  | ① 目标价 | 浮盈 +10% ~ +15%  | 止盈 1/3          |
  | ① 目标价 | 浮盈 +20% ~ +25%  | 再止盈 1/3         |
  | ② 破线  | 跌破 MA5 / MA10   | 各止盈 1/3         |
  | ② 破线  | 跌破 MA20         | 清剩余仓位           |
  | ③ 移动  | 浮盈 > 10%        | 止损上移至成本价（保本）    |
  | ③ 移动  | 自最高点回撤 8%       | 触发移动止盈          |

  - **原则**：止盈与止损**对称执行**——不能涨了舍不得卖、跌了割肉。

### FR-10 每日推送｜优先级：必须

### FR-14 多端交互体系｜优先级：H5 + AI 对话（首期必须）／大屏（期望·二期）

整体交互由 **① 消息推送（FR-10 / FR-11）② 大屏 ③ H5 ④ AI 对话** 四端构成，四端共享同一份数据与结论。

**统一原则**

- **FR-14.0.1 同源一致**：四端底层数据、信号、结论必须同源，同一时点各端展示口径一致，不得出现"推送说减仓、H5 说持有"。
- **FR-14.0.2 端间跳转**：推送消息可点击跳转到 H5 对应个股详情；H5 / 大屏中可就地发起 AI 对话追问。
- **FR-14.0.3 统一规范**：全部端遵守 A 股配色约定（**涨红跌绿**）、双层信息结构（人话结论 + 可展开明细）与免责声明。
- **FR-14.0.4 响应式**：大屏 / H5 为同一套内容的不同屏幕适配，功能集合一致，仅布局与字号按屏幕调整。
- **FR-14.0.5 实时同步（已确认）**：任一端修改持仓 / 权重 / 自选股后，各端**实时推送刷新**，无需重开页面。

  - 现有意图识别偏"查询 / 分析"，**写操作**（改持仓 / 调权重 / 设止损）的意图解析需扩展（对应 FR-14.3.3）。

### FR-17 场景 0 · 建仓与加仓信号（买入侧）｜优先级：必须

> 定位：面向**中长线持仓**（明确不做短线操作），解决"何时买入建仓、买入后何时加仓"。
> 所有买入侧信号**必须同时给出止损位**（与 FR-9.2 一致）。

**FR-17.1 建仓（首次买入）信号 —— 采用"中期趋势定方向 + 日线回踩定买点"的多信号共振（已确认口径）**

判断逻辑 = **趋势条件（必须满足）+ 买点条件（满足其一）**：

- **趋势条件（必须满足）**：**周线**趋势向上——周线 MA5 > MA10，或价格站上 MA60（年线/半年线）且 MA60 走平向上。确保是**中期向上**，而非短线反弹。
- **买点条件（满足任一即可）**：
  - **A｜突破回踩确认**：放量突破平台 / 箱体后，**回踩 MA20（或 MA60）不破并企稳**；
  - **B｜底部反转确认**：底部**放量** + **MACD 金叉或底背离** + **重新站上 MA20**。
- **辅助确认**：突破需放量、回踩需缩量；乖离率不过大（BIAS 不超 +10%，不追高）。
- **排除条件**：处于下跌趋势或趋势不明时**不提示建仓**；当日出现涨跌停、跳空缺口、消息驱动急涨等**异动**时**不提示**（等情绪稳定）。
- **不采用**：单一"MA5 上穿 MA10 金叉"作为建仓依据（震荡市假信号过多，不适合中长线）。

**FR-17.2 建仓仓位**：首次建仓 ≤ 3 成，**分 2 批**（先建 1.5~2 成，确认趋势后再补足）。首次建仓即设定止损位（跌破买点结构低点或 MA20）。

**FR-17.3 加仓信号 —— 金字塔加仓（已确认）**

- 仅在**已建仓且趋势向上（周线与日线不冲突）**时提示加仓；下跌趋势中不提示加仓（抄底走 FR-17.4）。
- 加仓触发（满足其一）：
  - **低吸加仓**：回踩 MA10 / MA20 不破并企稳；
  - **顺势加仓**：放量突破前高。
- 金字塔节奏（**越涨加得越少**）：首仓 3 成 → 涨一档加 2 成 → 再涨加 1 成，累计不超过上限（6~7 成）。
- 每次加仓**必须同步上移止损位**（成本抬高，止损随之抬高，保护浮盈）。

**FR-17.4 下跌中的加仓（抄底）—— 已确认：止跌确认后才分批加**

- 必须等**止跌信号**（FR-5.2 五项：缩量、长下影、KDJ 超卖金叉、MACD 绿柱缩短、底背离）出现后，**才**提示分批加仓；
- 单笔 ≤ 2~3 成，总抄底仓位不超过上限；
- **强制止损**：跌破前低立即离场（与 FR-5.4 一致）。

| **做 T** | 震荡趋势 | 布林带上下轨 / 箱体上下沿 + 支撑压力位；建议价差 ≥ 1.5% |

### FR-19 场内基金（ETF / LOF）支持｜优先级：必须

> 标的范围从"个股"扩展为"**个股 + 场内基金**"（对应 NG3 调整）。场内基金（ETF / LOF）用 A 股账户即可买卖，如港股红利 ETF **513530**。

- **FR-19.1 标的识别**：系统需识别标的类型（个股 / ETF / LOF），并按类型套用相应规则；添加时校验代码有效性与类型。
- **FR-19.2 技术分析口径（v0.7 调整）**：趋势与买卖点判断**以场内价格 K 线为主**（均线、MACD、KDJ、RSI、布林带等与个股一致），并叠加基金专属维度：
  - **跟踪指数（本期保留）**：以跟踪指数趋势校验场内价格趋势，指数与价格背离时提示。
  - **折溢价率 / 规模与流动性（本期降级不做）**：原计划叠加折溢价率、规模与流动性判断，因所用免费数据源（AkShare 等）能否**稳定提供尚未验证**，经需求方决策**本期降级为不做**（对应方案文档 R1）。待数据源验证通过、或引入付费源后，作为**后续迭代项**补回。
- **FR-19.3 基本面替代**：场内基金**无个股财报**，基本面维度以**跟踪指数 / 成分股基本面**与**基金分红**替代（与 FR-7 打通）。
- **FR-19.4 事件适配**：基金相关事件为**基金分红、份额变动、跟踪指数调整**等（见 FR-20）。
- **FR-19.5 规则复用与交易制度**：建仓 / 加仓 / 止盈 / 止损 / 做 T 等规则对场内基金同样适用；**交易制度按标的实际口径适配**——A 股个股与 A 股股票型 ETF 为 **T+1**，跨境 ETF 为 **T+0**。经核验，首批 4 只 ETF（513100 / 513180 / 513530 / 520660）**均为 T+0**（520660 经上交所上市交易公告确认"实施日内回转交易"），做 T 规则对上述 ETF 按 T+0 适配。
- **FR-19.6 品种边界**：本期支持场内 **ETF / LOF**；**不含场外基金、可转债、REITs**（后续可按需扩展）。

### FR-20 重大事件提醒与财报分析｜优先级：必须

> 解决"标的重大事件容易被忽略"的问题，区分**日历型（可提前预警）**与**突发型（需即时提示）**两类。

- **FR-20.1 事件日历（日历型，提前预警）**：对每只标的提前提示已知日程：
  - **财报预约披露日**（建议提前 1~3 日预警）；
  - **分红 / 送转 / 除权除息日**；
  - **限售解禁日、股东大会**等。
- **FR-20.2 突发消息与风险警告（突发型）**：及时提示——
  - 个股 / 行业**重大利好 / 利空**消息；
  - **风险警告**：ST / 退市风险、监管问询函 / 处罚、大股东减持、业绩预告变脸、商誉减值等。
- **FR-20.3 财报分析（财报公布后自动生成；已确认深度）**：财报公布后自动产出分析：
  - **关键指标**：营收、净利润、增速、毛利率、现金流、ROE；
  - **同比 / 环比**变化；
  - **是否超预期 / 不及预期**（与市场预期或同比比较）；
  - **一句话人话结论**（小白可直接看懂"这份财报好不好"）。
- **FR-20.4 推送方式（已确认）**：
  - **日历型事件**归入每日 **20:00** 概览的「**事件与风险**」板块；
  - **突发型重大事件**（重大利空、风险警告、财报暴雷 / 超预期）**单独高亮推送**（与 FR-10.4 紧急信号一致）。
- **FR-20.5 与建议联动**：事件影响计入 FR-7 的**消息面 / 基本面**维度，并在对应标的建议中标注"受某事件影响"。
- **FR-20.6 基金适配**：ETF / LOF 无个股财报，事件提醒以**基金分红、跟踪指数调整、成分股重大事件**替代。

## 6. 与现有工程的关系（仅背景参考，非技术方案）

> 本节仅说明本项目已有能力，便于后续方案阶段复用，**不构成本次需求的实现方案**。

现有工程（`daily_stock_analysis`）中已存在与本次需求高度相关的能力：

- 已内置趋势状态分类：`trending_up / trending_down / sideways / volatile / sector_hot`（与 FR-3 目标基本对应）。
- 已有战法骨架（`strategies/*.yaml`，共 15 个）：`bull_trend`（多头趋势/回踩低吸）、`box_oscillation`（箱体震荡/做 T）、`bottom_volume`（底部放量/超跌反转）、`shrink_pullback`（缩量回踩）、`ma_golden_cross`（均线金叉）等。
- 已有技术指标能力（MACD / KDJ / RSI 等在技术分析代理中已引用）。
- 已有多数据源适配（AkShare / Baostock / Tushare / Futu / 腾讯 / efinance 等）与降级机制。
- 已有多渠道通知（企业微信、飞书、钉钉、邮件、Telegram、Slack 等）。
- 已有图片渲染能力（可将 K 线/报告渲染为图片用于推送）。
- 已有 Web 前端（`apps/dsa-web/`）与桌面端（`apps/dsa-desktop/`，Electron），可作为 H5 / 大屏的落地基础。
- 已有 Agent 体系（`src/agent/`），可作为 AI 对话交互的落地基础：
  - `orchestrator.py` 多智能体编排（quick / standard / full / specialist 四档）
  - `agents/` 专业 Agent（技术面、情报/新闻、风险、决策综合、组合）
  - `memory.py` 分析结果记忆与置信度校准、技能胜率
  - `conversation.py` 会话与消息持久化
  - `web_intent_*.py` 对话意图识别（分词 + 意图标签）
  - `dashboard_payload.py` 看板载荷
  - `tools/backtest_tools.py` 回测工具

**能力缺口（本次需新增）**：

- `memory.py` 存的是**分析结论记忆**，**不是对话记忆**——"对话记录压缩成记忆"需新增一层**对话摘要压缩**（已立为 FR-15）。
- `web_intent` 偏"查询 / 分析"，**写操作**（改持仓、调权重、设止损）的意图解析需扩展（已写进 FR-14.3.3）。

**结论**：本次需求可在现有工程基础上扩展实现，而非从零搭建，并**确定复用现有 Agent 体系**（FR-16）。具体方案留待方案阶段。
