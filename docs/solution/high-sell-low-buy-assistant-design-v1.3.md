## 0. 摘要

在现有工程 `daily_stock_analysis`（A 股自选股智能分析系统）之上，扩展出一个面向**中长线个人投资者**的「**高抛低吸助手**」：每日 **20:00** 收盘后自动分析自选股，输出**建仓 / 加仓 / 分批止盈 / 减仓 / 清仓 / 抄底**的可执行建议，推送到**飞书**，并支持 **H5** 查看与 **AI 对话**操作。

**核心结论**：现有工程已具备约 **80%** 的底座（数据源、15 个战法、多智能体、多渠通知、定时调度、前端、回测），**本方案以"改造复用为主、少量新建"**。经 P0 详细设计逐表核对后修正：**信号层复用 `decision_signals`、持仓复用 `portfolio_*`、对话记忆改为扩展 `conversation_summaries`**；P0 真正需新建仅两处——**统一风控引擎（单标的级，FR-9）** 与 **自选股表 `watchlist_items`**（详见 P0 详细设计）。

**已确认的关键决策**

| 项 | 决策 |
| --- | --- |
| 数据源 | **先用工程现有免费源**（AkShare / Baostock 等），不足再扩 |
| LLM | **复用工程 `src/llm/` 现有配置**（litellm，多 provider） |
| 首期推送渠道 | **飞书机器人**（`feishu_sender.py` 已具备） |
| H5 | **改造复用 `apps/dsa-web/`** |
| 首期范围 | **消息推送 + H5 + AI 对话**；**大屏二期** |
| 标的 | A 股个股 **+ 场内基金（ETF / LOF）**；中长线（非短线） |
| 首批自选股 | 8 只（见 §5）：601169 / 601818 / 601919 / 000725 / 513100 / 513180 / 513530 / 520660 |
| 基金判据 | **降级**：本期只做"价格 K 线 + 跟踪指数校验"，**不做折溢价率 / 规模与流动性**（见 R1） |
| 飞书机器人 | **由需求方自行配置**（webhook / 应用凭证自理），方案侧仅预留配置项 |
| 回测排期 | 作为 **P1 上线前的规则体检关卡（gate）**：回测达标才开推送；P3 仍出完整回测报告 |

## 2. 总体架构

### 2.1 分层架构（五层）

```
┌─────────────────────────────────────────────────────────────┐
│  ⑤ 交互层  飞书推送 | H5(dsa-web) | AI对话(agent) | 大屏(二期)  │
├─────────────────────────────────────────────────────────────┤
│  ④ 呈现/推送层  formatters / md2img / notification_routing      │
├─────────────────────────────────────────────────────────────┤
│  ③ 决策层  多因子打分(FR-7) → 风控引擎(FR-9,新建) → 建议生成(FR-8) │
│            事件引擎(FR-20) 上下文注入                            │
├─────────────────────────────────────────────────────────────┤
│  ② 分析层  指标计算 → 场景引擎(FR-3~6,17) → 战法(strategies/)     │
├─────────────────────────────────────────────────────────────┤
│  ① 数据层  data_provider(多源+降级) → storage(SQLite) → 缓存      │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心数据流（每日 20:00）

```
20:00 scheduler 触发
  → 拉取自选股(个股+ETF) 日线/周线/资金/事件数据 (data_provider, 带降级)
  → 落库 (storage, 断点续传)
  → 指标计算(均线/MACD/KDJ/RSI/BOLL/BIAS) + 基金跟踪指数校验
  → 场景判定(上涨/下跌/震荡/变盘/背离) → 匹配战法
  → 多因子打分(技术/大盘板块/消息/基本, 权重可配)
  → 风控引擎(止损位/分批止盈/金字塔仓位)
  → 生成建议(四要素+纪律卡) + 事件与风险提示
  → 分级：常规入「每日概览」；紧急(止损/破位/重大利空)单独高亮
  → 渲染(文字+K线图) → 飞书推送
  → H5/对话端实时刷新（同源）
```

### 2.3 四端同源（FR-14.0.1 / NFR-9）

- **单一事实来源**：所有结论由"③ 决策层"产出后**落库**（`signals` 表），四端只读同一份数据，杜绝"推送说减仓、H5 说持有"。
- **实时同步**（FR-14.0.5）：写操作（改持仓/调权重）落库后，通过**变更通知**（后端事件 / 轮询）刷新各端。

### 2.4 部署形态（已确认）

- **本地个人电脑（Windows）+ 内网 + 免登录**（NFR-12）。
- 常驻方式：计划任务（Windows Task Scheduler）或 Docker（`docker/` 已具备）触发 20:00 任务；H5/大屏由本地服务提供，仅内网访问。

## 3. 关键子方案

### 3.1 数据层（FR-2 / FR-19）

- **多源 + 降级**：沿用 `data_provider/`（免费源优先，已确认）。
- **ETF / LOF 专项（R1 已决）**：新增**跟踪指数及成分股、基金分红**取数。原计划的**折溢价率、规模 / 成交额**取数，因 AkShare 等免费源稳定性未验证，经需求方决策**本期降级不做**（R1 由"风险"转为"已决"）；后续若验证通过或引入付费源，作为**迭代项**补回。
- **落库**：`storage.py`（SQLite / SQLAlchemy），配置项增加 `asset_type` 区分个股 / ETF / LOF。

### 3.2 指标与场景引擎（FR-3~6 / FR-17）

- 指标：均线、MACD、KDJ、RSI、BOLL、BIAS、量价（复用现有计算）。
- 场景判定：上涨 / 下跌 / 震荡 + 变盘 / 高波动 / 背离；**日线 + 周线**双周期。
- **建仓信号（FR-17.1）**：周线趋势向上（MA5>MA10 或站稳 MA60）**且**日线出现买点（放量突破回踩 MA20/MA60 不破，或底部放量+MACD 金叉/底背离+站上 MA20）。
- **加仓（FR-17.3）**：金字塔（3→2→1 成），回踩不破或放量突破前高触发，止损随之上移。
- 规则以**配置**形式落地（对应 FR-18 映射表），便于调参与回测。

### 3.3 多因子打分与权重（FR-7）

- 四因子：技术面 / 行业·大盘·板块 / 消息面 / 基本面；默认 **45 / 25 / 15 / 15**，可配（NFR-6）。
- 复用 `agents/decision_agent.py` 做综合；`intel_agent` 供消息面，`portfolio_agent` 供组合视角。
- 输出**可解释**：每个维度给独立结论 + 依据，前端可展开（FR-7.3/7.4）。

### 3.4 风控引擎（FR-9）— **新建**

工程内已有 `services/portfolio_risk_service.py`（**组合级**：集中度 / 回撤 / 止损接近度），但**缺"单标的级"止损止盈引擎**，故新建 `src/core/risk_engine.py`（示意），与组合级风险**并行使用**：

- **止损**：技术位止损（破 MA5/10/20 或破结构前低），买入类建议**强制附带**止损位。
- **分批止盈**（FR-9.5）：目标价 +10~15% / +20~25% 各 1/3；破 MA5/MA10/MA20 各 1/3、破 MA20 清剩余；移动止盈（浮盈 >10% 保本、最高点回撤 8%）。
- **仓位**：首建 ≤3 成（分 2 批）、上限 6~7 成、抄底单笔 ≤2~3 成。
- 触发后产出 `信号`，进入推送分级（紧急）。

### 3.5 事件引擎（FR-20）

- **事件日历（日历型）**：财报预约披露日、分红/送转/除权除息、解禁、股东大会 → 提前 1~3 日预警。
- **突发（突发型）**：重大利好/利空、风险警告（ST/退市、问询函、减持、业绩变脸等）→ **单独高亮推送**。
- **财报分析**：财报公布后自动输出 营收/净利/增速/毛利率/现金流/ROE + 同比环比 + 是否超预期 + 一句话结论。
- 复用 `event_driven.yaml`（事件驱动战法）+ `intelligence_service`（情报）+ `alert_service`（告警）。
- **基金适配**：ETF/LOF 无个股财报 → 以基金分红 / 跟踪指数调整 / 成分股事件替代。
- **实施状态（v1.3）**：✅ **已接线**——`src/services/event_source.py` 聚合情报源 + 预警源，按自选股名称/代码命中，风险/日历关键词自动标注，异常隔离降级；经 `P1PushService(event_provider=...)` 进入每日概览「事件与风险」板块（`--no-events` 可关闭）。**财报深度分析**（营收/净利/ROE 等结构化拆解）仍属后续迭代。

### 3.6 推送引擎（FR-10 / FR-11）

- **20:00 定时**：`scheduler.py` 触发；生成「每日概览」（全量 + 标红置顶 + 事件与风险板块）。
- **紧急单独推**：破止损 / 有效破位 / 重大利空（FR-20.4）。
- **渠道**：首期 **飞书**（`feishu_sender.py`）；**webhook / 应用凭证由需求方自行配置**（方案侧仅预留配置项，见 R4）；架构上保留多渠道（企微/钉钉/邮件）。
- **内容**：双层（人话结论 + 可展开明细）；关键信号附 K 线图（`md2img.py`）。
- **降噪**（NFR-3）：同类信号去重、无信号保持安静。
- **周六复盘**（FR-11）：复用 `market_review*` + `history_*`，含胜率、持仓盈亏、执行回填、下周关注。

### 3.7 交互层（FR-14）

- **H5**：改造 `apps/dsa-web/`（Vite+React+TS）→ 建议详情+K线、持仓录入/修改、历史信号与复盘、参数/权重调节；移动适配 + 二次确认（FR-14.2.6）。
- **AI 对话**：复用 `src/agent/`（orchestrator 分流）+ `bot/`（渠道）；新增**写操作意图**（改持仓/调权重/设止损）与**复合指令**（一句话多指令，FR-14.3.7）；操作后**必须回执**。
- **大屏（二期）**：复用 H5 内容做大屏布局适配（浏览器全屏、免登录常驻）。

### 3.8 对话留档与记忆压缩（FR-15）— **新建一层**

- `conversation.py` 已有消息持久化；**`conversation_summaries` 表已有"滚动摘要"**；`memory.py` 另有"分析记忆"。
- 故 FR-15 为**扩展**而非新建：在滚动摘要之上，补充**结构化长期记忆**（持仓与偏好变更、已确认操作、重要结论），**不覆盖原始对话**、可追溯、可删除。

## 4. 分期实施计划（WBS）

> **分期术语**：P0~P4 指**实施阶段 / 里程碑**（P0 为第一期内核，数字越小越靠前），**不是优先级**。所以下文的"回测是否纳入 P0"＝"是否在第一期就做回测"。

| 期 | 范围 | 交付 | 验收要点 |
| --- | --- | --- | --- |
| **P0 指标与风控内核** | 数据(含 ETF 跟踪指数取数) + 指标 + 场景引擎 + **风控引擎** + 建仓/加仓信号（用首批 8 只标的） | 可对首批标的输出"四要素建议+纪律卡" | 规则可回溯（FR-18）；参数可配 |
| **P1 每日推送闭环** | 20:00 调度 + 概览/紧急分级 + 飞书推送 + K线图 + 事件与风险 | 每天 20:00 收到可执行的飞书推送 | 时效、降噪、免责声明（NFR-2/3/5） |
| **P2 H5 + AI 对话** | dsa-web 改造 + Agent 写操作/复合指令/回执 + 记忆压缩 | 手机可看详情/改持仓；对话可问可改 | 四端同源（NFR-9）；操作可追溯（NFR-11） |
| **P3 复盘 + 回测** | 周六复盘 + 回测（近3年，601919/601288） | 复盘报告 + 策略有效性报告 | 胜率/盈亏比/最大回撤（FR-12.2） |
| **P4 大屏（二期）** | 大屏适配 | 大屏展示页 | 远距离可读、免登录常驻 |

> **回测排期（R3，已决）**：采用 **"P1 上线前的规则体检关卡（gate）"**——P0 内核建成后，先用近 3 年数据回测 601919 / 601288，确认 P0 规则有效（胜率 / 盈亏比 / 最大回撤达标）**才开每日推送**；**P3 仍产出完整回测报告**。即：回测不单独占一期，而是作为 **P0 → P1 之间的质量门**。
