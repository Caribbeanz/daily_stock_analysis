## 0. 摘要

P2 的目标是把 P1 的"**能推**"推进到"**能看、能问、能改、记得住**"的完整闭环，交付物为 **H5 移动端** + **AI 对话** + **结构化记忆** 三件事：

| 交付 | 对应需求 | 一句话目标 |
| --- | --- | --- |
| **A. H5 移动端** | FR-14.2 | 手机上点开推送即可看完整建议、改持仓、调参数，高频操作 ≤3 步 |
| **B. AI 对话** | FR-14.3 / FR-16 | 能问（为什么减仓 / KDJ 是什么 / 深度分析）、能改（一句话多指令改自选/持仓/参数）、**每次写操作有回执** |
| **C. 结构化记忆** | FR-15 | 对话完整留档 + 定期压缩成结构化记忆（持仓/偏好/已确认操作），可查看可删除 |

**核心工程判断（基于现状调研）**：现有 `apps/dsa-web`（React 19 + Vite 7 + Tailwind 4）、FastAPI（`/api/v1`）、Agent 体系（`AgentOrchestrator`）**均可复用**；真正的缺口集中在**四处**——① 移动端信息架构缺失；② 对话写操作能力为 0（Agent 全部只读）；③ 自然语言意图解析只有分词器、无 resolver；④ 记忆只有滚动摘要、无结构化长期记忆。本方案围绕这四处补齐。

## 2. 总体架构

在既有五层架构（`design-v1.3` §2.1）之上，P2 **新增两处**（★）并**扩展一处**（☆）：

```
┌───────────────── 交互层（FR-14）─────────────────┐
│  飞书推送(P1✅)  │  H5 移动端(★P2)  │ AI 对话(☆P2) │  ← 大屏(P4)
└───────────┬───────────────┬──────────────┬───────┘
            │               │              │
            ▼               ▼              ▼
    ┌──────────────────────────────────────────────┐
    │        API 层  FastAPI  /api/v1（复用）        │
    │  stocks / portfolio / decision-signals /       │
    │  agent / system  ＋ ★memory / ★actions         │
    └───────────┬───────────────┬──────────────────┘
                │               │
      ┌─────────▼──────┐   ┌────▼──────────────────┐
      │ ★意图层 intent  │   │  ★执行层 action_service│
      │ resolver(规则+LLM)│  │  确认→执行→回执→审计    │
      └─────────┬──────┘   └────┬──────────────────┘
                │               │
      ┌─────────▼───────────────▼──────────────────┐
      │   既有 Service 底座（复用，勿重写）           │
      │  AgentOrchestrator / decision_signal_service │
      │  watchlist_service / portfolio_service /     │
      │  position_service / system_config_service    │
      └─────────┬──────────────────────────────────┘
                │
      ┌─────────▼──────────┐  ┌────────────────────┐
      │  ★记忆层 memory     │  │  存储（SQLite/SQLAlchemy）│
      │  结构化记忆 + 压缩   │←→│  decision_signals /  │
      └────────────────────┘  │  portfolio_* / ★新表 │
                              └────────────────────┘
```

**新增模块（★）与职责**

| 模块 | 路径（建议） | 职责 |
| --- | --- | --- |
| 意图解析 | `src/agent/intent/resolver.py` | 自然语言 → 结构化意图（查询 / 操作 / 复合），规则优先 + LLM 兜底 |
| 执行门面 | `src/services/action_service.py` | 写操作统一入口：**确认 → 执行 → 回执 → 审计**（单一写点） |
| 记忆服务 | `src/services/chat_memory_service.py` | 结构化记忆的写入 / 压缩 / 查询 / 删除 |
| 移动布局 | `apps/dsa-web/src/components/mobile/` | 移动端信息架构（`MobileShell` + `useMediaQuery`） |
| 个股详情页 | `apps/dsa-web/src/pages/StockDetailPage.tsx` | 单只标的完整视图（H5 主入口） |

**核心数据流**

1. **推送 → H5（FR-14.0.2）**：飞书消息内链接 → `/m/stocks/:code?from=push` → 详情页（**限内网可达**，见 §6.2）。
2. **对话 → 读**：H5/飞书消息 → 意图 = 查询 → `AgentOrchestrator`（按复杂度分流 quick / full / portfolio）→ 回答（附风险提示）。
3. **对话 → 写（FR-14.3.3）**：消息 → 意图解析（可多指令）→ **二次确认** → `action_service` → 调既有 service → **回执**（做了什么 + 当前状态）→ 落审计。
4. **记忆（FR-15）**：会话消息持续落库 → 定期/阈值触发压缩 → `chat_memory_service` 产出结构化记忆 → 注入后续对话上下文。

## 3. 关键子方案

### 3.1 A · H5 移动端（FR-14.2）

**设计原则**：**同一套前端工程做移动适配**（D1 已决），不新建项目、不重复造页面——复用现有 axios 封装（`src/api/index.ts`，默认同源 baseURL）与 zustand store。

| 子项 | 方案 | 需求 |
| --- | --- | --- |
| 移动布局层 | 新增 `useMediaQuery` + `MobileShell`（底部 Tab：**自选 / 持仓 / 对话 / 设置**），桌面端沿用现有 `Shell.tsx` 侧边栏 | FR-14.0.4 |
| 个股详情页 | 新建 `StockDetailPage`（路由 `/m/stocks/:code`）：**人话结论**（顶部大字号）+ **四要素**（建仓区间 / 止损 / 目标 / 仓位建议）+ K 线 + 多因子明细（可展开）+ 事件与风险 | FR-14.2.1 |
| 持仓编辑 | 复用 `/portfolio` 能力，移动端简化表单（代码 / 成本价 / 数量），调 `position_service` | FR-14.2.2、FR-1.3 |
| 历史信号与复盘 | 移动端列表视图接 `/decision-signals` + `outcomes/stats` | FR-14.2.3 |
| 参数 / 权重调节 | 移动端表单 → `preview` 接口先看结论变化 → 确认保存 | FR-14.2.4、FR-7 |
| 高频操作 ≤3 步 | 首页推送卡 →（1 点）详情 →（2 点）改持仓 →（3 步内）确认 | FR-14.2.5 |
| 防误操作 | 只读 / 修改视觉区分；**所有写操作二次确认** | FR-14.2.6 |
| 推送跳转 | 飞书消息链接指向 `/m/stocks/:code`（**内网可达性说明见 §6.2**） | FR-14.0.2 |
| 视觉统一 | 涨红跌绿主题变量（Tailwind token），四端一致 | FR-14.0.3 |

### 3.2 B · AI 对话（FR-14.3 / FR-16）

**按复杂度分流（FR-16.2）**

| 请求类型 | 通道 | 复用 |
| --- | --- | --- |
| 日常问答 / 术语解释 / 查询 | **轻量对话**（单轮 LLM + 上下文记忆） | `chat_executor` + `llm_adapter.call_text` |
| 个股深度分析 | **full 多智能体流水线** | `AgentOrchestrator.run(full)` |
| 持仓整体风险体检 | **组合分析** | `portfolio_agent` |

**写操作：三段式「解析 → 确认 → 执行 → 回执」（FR-14.3.3 / FR-14.3.7）**

```
用户: "把技术面权重调到 60% 并把 600519 止损设为 15 元"
  │
  ├─① 意图解析（intent/resolver）
  │     ├─ 规则匹配（复用 tokenizer 词表：action_portfolio / request / time...）
  │     └─ LLM 兜底 → 输出结构化意图列表（**逐条**）
  │         [ {op: set_weight, factor: technical, value: 0.60},
  │           {op: set_stop_loss, symbol: 600519, value: 15.0} ]
  │
  ├─② 二次确认（FR-14.2.6）
  │     H5：确认卡（列出"将要做什么"）；飞书：回复「确认 / 取消」
  │
  ├─③ 执行（action_service → 既有 service；单一写点）
  │     白名单校验 → 调 watchlist_service / position_service / system_config_service
  │
  └─④ 回执（FR-14.3.3）：**逐条**"做了什么 + 当前状态"
        例：「✅ 技术面权重 45%→60%（当前：技术60/消息15/基本15/大盘10）」
            「✅ 600519 止损已设为 15.00」
```

**动作白名单（**已决 §6-D2**）**

| 动作 | 复用服务 | 需二次确认 | 备注 |
| --- | --- | --- | --- |
| 增 / 删自选股 | `watchlist_service` | **是** | FR-1 |
| 设置 / 移除持仓 | `position_service` | **是** | P1 已交付 |
| 调四因子权重 | `system_config_service` | **是**（先预览） | FR-7 |
| 设置止损 | `system_config_service` / 持仓 | **是** | FR-9 |
| 触发个股分析 | `AgentOrchestrator` | 否（只读） | FR-14.3.4 |
| 回执「已执行 / 忽略 / 稍后」 | 记入执行统计 | 否 | FR-14.3.5 |
| **直接下单交易** | — | **禁止**，明确拒绝并给替代路径 | FR-14.3.9 |

> **D2 决议口径**：白名单**不外扩**（不开放"触发分析"以外的重动作）；**全部写操作一律二次确认**，无例外。所有写操作均落在单一写点 `action_service`。

**合规与兜底（FR-14.3.8 / FR-14.3.9）**：所有涉及买卖的回复**强制附风险提示**；越界请求（如下单）明确说明"做不到"并给替代路径，不得臆造。

**入口（FR-14.3.1）**：H5 内嵌对话（`ChatPage` 移动化）+ 飞书机器人对话（复用 P1 通道）。

**权限（已决 §6-D4）**

| 入口 | 读 | 写 |
| --- | --- | --- |
| H5（内网，免登录） | ✅ | ✅（二次确认） |
| 飞书 · 白名单 `open_id`（本人） | ✅ | ✅（回复「确认」后执行） |
| 飞书 · 群内其他人 | ✅ | ❌ **只读**，写请求回复"无权限" |

### 3.3 C · 结构化记忆（FR-15）

现状只有 `chat_context.py` 的**滚动摘要**（非结构化文本，落 `ConversationSummary`）。P2 在其上叠加**结构化长期记忆**（与 `memory.py` 的"分析记忆"明确区分）。

| 需求 | 方案 |
| --- | --- |
| FR-15.1 留档 | **已完成**：`conversation_manager` + `ConversationMessage` 表持久化全部会话消息 |
| FR-15.2 压缩 | 复用 `chat_context` 触发机制（token 阈值 / 周节奏），**扩展产出结构化条目** |
| FR-15.3 记忆内容 | 新增 `ChatMemory` 表：`type ∈ {position_change, preference, confirmed_action, analysis_conclusion}`、`content`、`source_message_ids`、`created_at`、`status` |
| FR-15.4 可追溯 | 每条记忆持 `source_message_ids` **回链原始消息**，压缩**不覆盖**原文 |
| FR-15.5 可管理 | H5「记忆」页 + API：列表 / 查看来源 / 删除（软删 + 硬删） |

**压缩与保留策略（已决 §6-D5）**

| 项 | 决议 |
| --- | --- |
| 压缩触发 | ① token 阈值触发（沿用 **12000**）；② 每周固定一次（配合 FR-11 周六复盘）；③ 会话结束时增量压缩 |
| 原文保留 | **不自动删除**：会话原文长期保留（本地 SQLite，容量压力可忽略），压缩**只增不删** |
| 记忆条目保留 | 长期保留；删除由用户显式触发 |
| 用户可管理 | 列表 / 查看来源 / 软删（`status=deleted`，保留可审计）/ 硬删 / **一键清空**（需强确认） |

### 3.4 四端同源与实时刷新（NFR-9 / FR-14.0.5）

- **同源**：全部读写落在 `decision_signals` + `portfolio_*`（P0/P1 已建为唯一写入点，四端读同一份）。
- **实时刷新**：复用现有 **SSE** 基础设施（`/agent/chat/stream` + 前端 `useTaskStream`）；任一端发生写操作 → 广播 `invalidate` 事件 → 各端增量刷新，**无需重开页面**。
- **防漂移**：写操作统一走 `action_service`，避免"推送说减仓、H5 说持有"。

### 3.5 操作审计与可追溯（NFR-11）

新增 `ActionAudit` 表：`id / source(h5|feishu) / actor / action / target / before / after / confirmed(bool) / status / created_at`。

- 每次写操作**先审计后执行**（或同事务），保证"做过什么"可回放；
- 复用 `src/agent/tools/execution.py::build_tool_audit` 的脱敏审计思路；
- 提供查询接口供 H5「操作记录」查看 + 支持撤销（撤销 = 反向操作，同样走 `action_service` 并留审计）。

### 3.6 安全与访问方式（R6 / **D6 已决**）

**结论：只做内网直连，不做外网访问。**

| 项 | 决议 |
| --- | --- |
| 监听 | FastAPI 监听**内网 IP + 端口**（如 `192.168.x.x:8000`），手机与主机处于**同一局域网**即可访问 |
| 外网访问 | **不做**：不引入反向代理、不带 HTTPS / 证书 / 域名、不做公网端口映射（**不在 P2 范围**；如后续需要，另开变更） |
| 免登录 | 沿用现有免登录语义（内网 + 单机使用场景），**无账号体系** |
| 写权限闸门 | ① 飞书对话：**`open_id` 白名单**（仅本人可写，群内其他人只读）；② 所有写操作**二次确认** |
| CORS | 收紧白名单（现有 `api/app.py` 已配，实施时核对） |
| 暴露面 | 因不开放公网，RK5（误暴露公网）风险由"缓解"降为"**结构上消除**" |

### 3.7 构建与发布（**D7 已决**）

| 项 | 决议 |
| --- | --- |
| 构建 | `apps/dsa-web` 本地 `npm run build` → 产物落根 `static/`，由 FastAPI 托管（**沿用现状，不改链路**） |
| 发布 | 无需发布动作：重启 FastAPI 即生效（内网直连，无 CDN / 无灰度） |
| CI 打包 | **P2 不引入**。理由：单人内网使用，构建频率低，引入 CI 的收益（防回归 / 可追溯）低于维护成本；如 P3/P4 需要再评估 |
| 版本一致性 | 后端 API 与前端产物同仓同提交，避免版本错配；前端构建产物的**变更纳入提交说明**（便于回溯"某次改动后 H5 长什么样"） |

## 8. 验收标准（P2 整体）

1. **H5**：手机（**同一内网**）点开推送链接 → 3 步内看到完整建议并完成一次持仓修改；竖屏可读；涨红跌绿。
2. **对话 · 读**：能问"为什么建议我减仓""KDJ 是什么"，回答小白友好、附风险提示；"帮我分析 601919"能出结构化结论。
3. **对话 · 写**：一句话多指令（如 §3.2 示例）可**逐条解析、逐条回执**；改持仓/权重/止损落库正确；越界请求明确拒绝；飞书群内非白名单用户写入被拒。
4. **记忆**：对话完整留档；能查看结构化记忆并回链原文；能删除（软删 / 硬删 / 一键清空）。
5. **可追溯**：任一写操作可在 `ActionAudit` 查到 before/after。
6. **同源**：同一时点四端口径一致（推送 / H5 / 对话）。
7. **访问方式**：服务仅内网可达，未做任何公网暴露（D6）。
8. **测试**：新增单测全绿；整体回归不破坏 P0/P1 的 164 项。
