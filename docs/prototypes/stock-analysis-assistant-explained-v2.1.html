0先记住三件事

如果只看一屏，看这里。其余内容都是对这三件事的展开。

①

结论由代码算，不由大模型猜

大模型只负责把算好的结果写成一段人话。它不改数字、不给新建议、不参与打分。这样结果每天可复现、可回测。

②

先定阶段，再谈打法

先判断这只票处在上升 / 震荡 / 下跌 / 筑底哪个阶段，再决定这个阶段允许做什么。下跌阶段任何买入都会被拦下——这是本轮你新增的核心要求。

③

只给条件单，不替你下单

输出的是「如果涨到 X 就买 N 股」的静态清单，有效期只有当天。工具不接券商、不监控盘中、不自动成交，也不承诺收益。

明确不做的事（来自你的原话第 12 条）：不做盘中实时分析、不自动交易、不融资杠杆、不做消息面情绪判断、不承诺收益、不换股推荐。这些在需求里被写成 10 条「护栏」（NG-1～NG-10），任何后续改动都不能突破。

2系统全景：数据怎么变成你早上看到的那张卡

从最底层的数据，到你手机里的一条飞书消息，一共 5 层。关键设计是：中间只算一次，后面所有页面和推送都只读同一份结果，避免三处算出三个不同结论。

图 1：系统五层架构。橙色两个环节（风险守卫、阶段门）只做「收紧」，不做「放宽」。
为什么要「只算一次」：如果列表页算一遍、详情页算一遍、飞书再算一遍，只要取数时间差几秒，三个地方的数字就可能不一致——你会不知道该信哪个。所以需求规定：盘前生成一份带三元组的快照，所有出口只读它。

3决策引擎：一只票的建议是怎么算出来的

这是整份需求最核心、也最专业的部分。下面用「流程图 → 八步拆解 → 阶段 → 风险 → 条件单」五个角度，把它讲成白话。

一句话原理：先按技术面为主的权重算出「候选动作」，再依次经过风险守卫和阶段门两道关卡把不允许的动作砍掉，剩下合规的动作就是今天的建议；最后按建议方向生成可以照抄的条件单。

3.2 八步工作流：每一步在干什么、为什么要这么设计

0

先判阶段：这只票现在处于什么状态 你本轮新增

用价格和 MA20 的关系、MA20 斜率、均线排列、60 日箱体、位置分位，算出 5 档之一：上升 / 高位震荡 / 下跌 / 低位筑底 / 无法判定。需连续 2 天满足才切换，防止一天波动就换打法。

为什么：你说的「先给阶段定位，再做分析」。如果不先定阶段，评分会把「下跌中继」误当成「震荡低吸」，在下跌途中一直加仓。
1

三元组校验：这份数据是不是「今天的」

数据日期、快照编号、计算版本三者必须一致。对不上就显示「待同步」，不显示旧值。

为什么：避免你早上看到的是昨天的缓存，却以为是今天的建议。
2

状态位判定：停牌、数据不足直接标灰

停牌标「不可操作」，数据不足标「无数据 / 不生成意见」。「观望」是有效结论，不是没数据——两者严格区分。

为什么：你原话要求「数据不足标数据不足，不生成操作意见」。把没数据画成观望，会让你误以为系统分析过。
3

评分：技术面主导，其他低权重加减分

趋势档（偏强/中性/偏弱）+ 位置标签 + 关键价位 + 量能决定主档位；大盘、板块、财报、分红、消息只做加减分与置信度调整。

为什么：你明确说「技术面为主，其他作为一定权重参考」。低权重不是「不参与」，而是不能单独把建议从持有翻成加仓。
4

关卡① 风险守卫：先看有没有红灯 只收紧

7 类风险信号取最高等级：观察（灰）只降置信度；警示（黄）主档不变但禁止买入；严重（红）强制建议降级或触发先减后清。多条信号不叠加升级。

为什么：你说的「风险提醒甚至参与决策」。做成硬性关卡，是为了让风险真的能拦住买入，而不是只在卡片角落写一句提示。
5

关卡② 阶段门：这个动作在当前阶段允许吗 只收紧

评分给出一个候选动作后，检查它是否在阶段允许集合里。比如 S3 下跌阶段只允许减仓 / 清仓 / 观望，如果评分给出「加仓」，就改写成「等待买点」或「减仓」，并留痕 stage_gate_hit。

为什么放在评分之后：要先有候选动作才能判断要不要改；而且这样回测时能看到「如果没有阶段门，这天本来会建议加仓」，能量化这道关卡到底拦住了多少次错误买入。
6

仓位校验：单只 20% / 总仓 80% / 现金 20% / T 仓 10%

硬上限优先级最高，越界就把仓位建议裁剪到 0，但不改建议档位。行业集中度 ≥25% 只提示、不强制。

为什么：你的原话要求「统一硬上限 + 行业集中度只提示」。档位和仓位分开，是为了让「方向」和「能买多少」互不干扰。
7

生成条件计划：把建议翻译成可以照抄设单的清单

按阶段选模板，列出 5 类互斥情景。每条给：触发价格 → 动作与股数（取整到 100 股）→ 金额占比 → 有效期（仅当天）→ 仓位校验 → 能否直接设单。动作必须与 advice 同向，反向的一律输出「不操作 + 原因」。

为什么：你的原话「便于提前设置条件单，以免因为上班错过盘中行情」。不给概率、不排序，是因为这是条件预案，不是预测。

3.3 五阶段与各自的打法

这是你本轮最关心的新增：不同阶段，交易思路完全不同。下面这张图就是系统的「阶段→打法」对照表。

S1

上升趋势

主打法：回踩买 + 突破买，不追高。触发价来自 MA20 附近或前期高点。
禁止：用箱体上沿逆势高抛、越涨越买
S2

高位震荡

主打法：箱体高抛低吸做 T，底仓不动。上沿减、下沿买。
禁止：追突破重仓、在箱体中部开仓
S3

下跌趋势

主打法：反弹减 + 破位清，不抄底。卖点主要挂在反弹压力位，而非只挂破位。
禁止：任何买入（含 T 低吸、补仓摊薄、"估值低所以买"）
S4

低位筑底

主打法：观察为主，右侧确认才买（站上 MA20 + 放量 + 突破箱体上沿）。
禁止：左侧越跌越买、把「便宜」当买点
S0

无法判定

主打法：不出策略、不出计划，只显示状态位和原因。
禁止：用旧结论顶替
阶段门的实际效果（举例）：同一只票处在 S3 下跌阶段，评分算出「加仓」→ 阶段门发现「加仓」不在 S3 允许集合内 → 改写成「减仓」，并记下"原本想加仓、被阶段门拦下"。回测时就能统计这道关卡一共拦住了多少次在下跌途中的买入。
关于缠论：你提到「或类似缠论等理论支撑」。需求只落地了两层容易稳定计算的概念——「中枢≈箱体」「走势类型≈趋势/盘整」；背驰只作观察注记；笔、线段、级别递归本期不做，因为不同实现会给出不同结论，会让回测失去可复现性。项目自带的缠论文件是自然语言策略，按规则不直接接入决策。

3.4 风险体系：从"提示一下"升级为"能拦住买入"

你原话第 15 条要求风险「甚至参与决策」。需求把风险做成了 7 类信号 + 3 级动作，下面是它们各自能做什么。

观

观察级 灰

只下调置信度，建议档位不变。默认折叠，给一句人话。例如：大盘数据降级、 dividend 除权日临近。

警

警示级 黄

主档不变，但禁止加仓 / 建仓 / 买入类意见，不下发新的做 T 计划。例如：大盘连续偏弱、板块持续弱于大盘、财报渐进恶化。

严

严重级 红

强制建议降级或触发先减后清，禁止任何买入，仓位只减不增。例如：财报爆雷、跌破趋势失效位、分红中断、价值陷阱。

7 类风险信号包括
① 大盘环境（转弱 / 失守 / 数据降级）—— 最高只到警示级，不单独清仓
② 板块与低估陷阱 —— 其中 SEC-2 价值陷阱对应你说的「行业低估受挫」：估值低但还在跌，触发严重级
③ 个股基本面变坏 —— 财报爆雷（严重）/ 渐进恶化（警示）/ 取数失败（观察，不算基本面变坏）
④ 技术面变差 —— 跌破失效位触发先减（L1），继续跌才清（L2）
⑤ 分红与估值 —— 分红中断（严重，因为你的分红兜底逻辑被破坏）、估值与价格双高（警示）
⑥ 组合与仓位 —— 逼近硬上限、集中度过高、成本倒挂 + 高仓位
⑦ 数据质量 —— 连续 3 日取数失败、用缓存；不许伪装成基本面或技术面风险
防滚雪球规则：同一标的有多条信号时取最高等级；3 条警示 ≠ 1 条严重；禁止类动作取并集，但「建议降级」只执行一次。这条很重要——否则风险多了会一路把建议砍到清仓，反而不合理。
